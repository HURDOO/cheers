두 안 모두 프로덕션 빌드와 주요 화면은 동작한다. 현재 그대로 첫 홍보에 쓰기에는 수정할 문제가 남아 있다. D는 행사 참가자의 빠른 탐색에 적합하지만 미완성 목록과 재생 상태를 정리해야 한다. E는 이야기와 영상 비교 구성이 더 채워져 있지만 모바일 탐색과 직접 링크 이동을 보완해야 한다.

## D안

### 공개 전 수정: 영역 사이의 중복 재생

재현 순서: 연세 관점에서 원시림 → Woo 현장 영상 → 사랑한다 이글스 야구장 버전 재생.

자동재생 iframe이 순서대로 1개, 2개, 3개 남는다. 이전 영역 영상이 해제되지 않아 소리가 겹칠 수 있다. 필수곡·다시 듣기는 내부적으로 하나를 공유하지만 라이벌리와 야구 영역은 각각 독립 재생 상태를 가진다.

- 관련 파일: `src/events/korea-yonsei-games-2026-d/SongSections.tsx:76`, `RivalryStory.tsx:76`, `BaseballStory.tsx`.
- 조치: 페이지 전체 재생 상태를 공유하거나 새 재생 시 이전 플레이어를 중단한다.
- 완료 기준: 세 영역을 연속 재생해도 활성 iframe이 하나만 남는다.

### 공개 전 범위 정리: 다시 듣기 16곡 중 14곡은 검색으로 연결

| 영역 | 고려대 | 연세대 |
| --- | --- | --- |
| 필수곡 | 6/6 공개·영상 연결 | 6/6 공개·영상 연결 |
| 다시 듣기 | 8개 표시, 1개 영상·상세 연결 | 8개 표시, 1개 영상·상세 연결 |

고려대는 영원하라, 연세대는 해야만 공개본의 영상과 상세가 있다. 나머지 14곡은 시안 데이터로 표시되며, 선택하면 사이트 내 재생 대신 YouTube 검색 링크가 나온다. 엘리제를 위하여에서 직접 재현했다.

관련 파일: `src/events/korea-yonsei-games-2026/eventContent.ts:20`, `src/events/korea-yonsei-games-2026-c/KoreaYonseiGamesCPage.tsx:484`.

첫 공개에서는 준비된 곡만 표시하거나 이 영역을 접어두는 편이 빠르다. 전체 16곡을 약속하려면 영상을 채우고 각 곡의 공개 범위를 검수해야 한다. 라이벌리 영역은 별도의 시안 영상 보완이 있으므로, 카탈로그에서 미공개라는 이유만으로 재생 불가라고 판단하면 안 된다.

## 공통 공개 준비

### 1. 잘못 연결된 대표 영상 수정

`content/editorial/songs/korea-university-seungni-ui-hamseong/song.json:57`의 1번 영상은 `6M41kbUyd7E&t=12`이며, 영원히와 완전히 같다. 현재 편집본과 공개 릴리스 모두 같은 상태다. 새 영상 선별 또는 기존 영상의 적합한 구간 확인 → 편집 저장 → 재공개 → 새 빌드 순서가 필요하다. 생성 카탈로그만 직접 고치면 다음 릴리스 때 다시 덮일 수 있다.

영상 제목 확인: [현재 연결된 영원히 영상](https://www.youtube.com/watch?v=6M41kbUyd7E&t=12s).

### 2. 공식 일정과 입장 조건 확인

- 합동응원전의 9월 22일 및 신촌 노천극장은 [연세대 장애학생지원센터 공지의 검색 결과](https://graduate.yonsei.ac.kr/ablecenter1/able01/open01.do?articleNo=479770&mode=view)와 [RC교육원 공지의 검색 결과](https://uc.yonsei.ac.kr/yonseirc/program/program-notice.do?article.offset=0&articleLimit=10&articleNo=15231&mode=view)에서 확인했다. 해당 본문을 도구로 완전히 열지는 못했다.
- 정기전 10월 2~3일은 [고려대 8월 26일 학사일정 변경 공지](https://cpp.korea.ac.kr/bbs/pubs/151/272051/artclView.do) 본문에서 확인했다.

- 합동응원전이 가까운 목적에 맞춰 지난 OT보다 다음 행사 날짜·시간·장소를 눈에 띄게 표시하는 편이 좋다.

### 3. 홍보용 페이지 정리

두 HTML 모두 `noindex, nofollow`이고 `og:image`, `og:url`, canonical이 없다. 직접 링크 방문을 막는 상태는 아니지만 검색 노출과 공유 미리보기 준비가 덜 된 상태다.

- 정식 URL, 페이지 제목, 공유 설명·이미지를 확정한다.
- 검색 노출을 원하는 공개 페이지에서만 noindex를 해제하고 canonical/og:url을 맞춘다.
- 데스크톱의 A/B/C/D/E 시안 비교 메뉴는 공개 목적에 맞게 제거하거나 실제 서비스 탐색 이름으로 바꾼다.
- E에는 비공식 아카이브임을 알리는 문구와 공식 행사 공지 링크를 보완하는 편이 좋다.

### 4. 배포 재현성 확보

현재 D/E 소스·HTML, 공용 이벤트 코드, 로고 파일, 생성 카탈로그, 릴리스 스냅샷 등이 Git 미추적 상태다. 로컬 빌드 성공만으로 원격 배포에 파일이 포함된다고 볼 수 없다.

- 배포할 버전에 필요한 소스, 자산, `src/data/generated/catalog.json`, 대응 `content/releases/` 스냅샷을 함께 포함한다.
- 현재 Vite 빌드는 A/B/C/D/E와 다른 이벤트 페이지도 생성한다. 공개할 경로와 시안 접근 범위를 결정한다.
- 문서상 운영 배포 대상·도메인 연결은 아직 확정되지 않았다. 실제 배포 상태는 이번에 확인하지 않았다.
- 새 버전으로 전체 검사를 통과시킨 뒤 공개 도메인의 깊은 URL, 새로고침, 학교 파라미터, 앵커, 아카이브 이동, 이미지·폰트, HTTPS를 검사한다.
- 실제 휴대폰과 홍보할 앱의 내장 브라우저에서 대표곡 재생 및 공유 카드를 확인한다.

## 권장 실행 순서

1. 공통 영상 오연결 수정 및 재공개.
2. D의 중복 재생 수정과 다시 듣기 범위 축소. E의 모바일 바로가기와 직접 해시 진입 수정.
3. 행사 공지·입장 조건 및 시안에 고정된 영상 목록 검수.
4. 정식 주소·공유 카드·시안 메뉴 정리와 배포 파일 포함 여부 확인.

합동응원전에 갈 학생에게 바로 쓸 가이드를 제공하려면 D의 짧은 동선이 유리하다. 야구 응원가에서 흥미를 끌어 양교를 소개하려면 E의 구성이 유리하다. 완성도 때문에 하나를 폐기할 단계는 아니며, 두 안의 공개 전 수정 범위를 제한하는 것이 적절하다.
